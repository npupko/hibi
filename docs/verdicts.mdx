`hibi check` resolves every claim against the working tree, consults the judge cache, runs the [contradiction pass](/conflicts), and prints one **verdict** per claim. Verdicts are computed at check time and never stored. Only judge answers are cached.

```sh
hibi check                      # every claim
hibi check --doc CLAUDE.md      # the claims on one document; expired gates here
hibi check --since origin/main  # the claims touching a file changed since the ref
```

`check` writes nothing except new judge cache entries in `.claims/judge/`.

## Axes

| axis | values | present |
|---|---|---|
| `doc` | `unchanged`, `moved`, `changed`, `ambiguous`, `orphaned` | always |
| `evidence` | the same five, plus `unavailable` | when the claim has evidence sides; the worst state over them |
| `judge` | `supported`, `refuted`, `review`, `pending` | when a judgment applies: `reference` claims, and `attested` claims with judged evidence |
| `expired` | boolean | always; see [Attestations](/attestations) |
| `conflicts` | `[{ claimId, probability, reason }]` | always; empty when there are none |

The anchor states are defined on [Anchors](/anchors). The judge states are defined on [Judge](/judge).

For a `reference` claim, the judge is consulted only when both sides are `unchanged` or `moved`. Otherwise the reasons say `judge: not consulted while the doc side is <state>` or `... the evidence side is <state>`, and `judge` is absent. For an `attested` claim, `judge` comes from the newest cached `supports` verdict for evidence submitted with `hibi evidence`.

## gates, warns, reasons

Each verdict has two booleans and a list of labels:

| field | meaning |
|---|---|
| `gates` | the verdict fails the check |
| `warns` | the verdict needs attention and does not fail the check; never `true` together with `gates` |
| `reasons` | every reason label: anchor changes (prefixed `doc:` or `evidence:`), judge outcomes (prefixed `judge:`), conflict findings, expiry, worklist membership, and gating rules |

Every rule hibi applies shows up as a label. A label you do not understand is a question for the code, not a hidden rule.

## The gating table

| condition | `check` | `check --doc` |
|---|---|---|
| `changed`, `orphaned`, or `ambiguous` on either side | gate | gate |
| `judge: refuted` (only produced at or above `judge.threshold`) | gate | gate |
| a conflict at or above `judge.threshold` | gate | gate |
| `expired` | warn | gate |
| `moved`, `review`, `pending`, `unavailable` | warn | warn |
| a conflict in review, or a conflict check pending | warn | warn |
| `suggested` or `retired` claim | never | never |

A `suggested` claim that would gate or warn gets the label `suggested claim: never gates or warns`.

## Exit codes

| code | meaning |
|---|---|
| `0` | clean, or warnings only |
| `2` | at least one verdict gates; or, under `--fail-on warn`, at least one warns |
| `1` | operational error: no store, an unknown flag, an unknown `--since` ref, an invalid input |

`--fail-on` sets the threshold:

| `--fail-on` | exit 2 when |
|---|---|
| `gating` | a verdict gates (the default) |
| `warn` | a verdict gates or warns |
| `never` | never; the JSON still reports everything |

## Remediation

A verdict that needs action carries `remediation`: a menu, most severe condition first. `recommended` names the action to start with, or is `null` when hibi cannot know which is right. `--no-hints` (or `HIBI_ADVICE=0`) drops the menu.

| condition | actions, in order |
|---|---|
| a side `orphaned` | `reanchor` (runs `hibi reanchor <id> --suggest` to find the span), `retire`, `supersede` |
| both sides `changed` | `reconcile`, `reanchor`, `retire` |
| evidence `changed` | `update-claim` (rewrite the sentence if it is now wrong, then reanchor), `reanchor`, `retire` |
| doc `changed` | `reverify-doc`, `reanchor`, `retire` |
| a side `ambiguous` | `reanchor` with a wider span |
| `judge: refuted` | `fix-evidence`, `fix-claim` (no reanchor) |
| conflicts | `reconcile` (names the other claim), `ack` |
| `expired` | `attest` (a human vouch), `evidence` |
| `judge: review` | `ack`, `evidence` |
| a side `moved` | `reanchor` |

Each action has `id`, `title`, `rationale`, and a `command` when one exists. `pending` and `unavailable` add no actions; the reason label says what is missing.

## The worklist

`check` output includes `worklist[]`: the claims an agent should re-check now. A live claim on an active document is listed when:

| reason | claims |
|---|---|
| `expired` | an `attested` claim whose ttl ran out |
| `review` | a `reference` or `attested` claim whose judge state is `review` and not acknowledged |
| `pending` | a `reference` or `attested` claim whose judge state is `pending` |
| `never-checked` | an `attested` claim with no judged evidence yet |

A claim is listed once, with the first matching reason in the order above. Its verdict also carries a `worklist: …` reason. `hibi list --state pending` returns the same claims.

Each item:

| field | meaning |
|---|---|
| `claimId`, `sentence`, `kind` | the claim |
| `document` | the claim's document path |
| `procedure` | `{ instructions, steps? }` or `null` |
| `sources` | `[{ id?, resource, title? }]` |
| `owner` | the actor to contact, or `null` |
| `lastEvidence` | `{ summary, source, at, by }` from the newest judged evidence, when there is any |
| `reason` | `expired`, `review`, `pending`, or `never-checked` |


| top-level key | meaning |
|---|---|
| `ref` | the git HEAD, or `WORKTREE` when there is no commit |
| `since`, `changedFiles` | with `--since` only |
| `doc`, `found` | with `--doc` only; `found` is false when no claim is recorded on that document |
| `summary` | counts; `retired` claims are in none of `gating`, `warning`, `clean` |
| `summary.conflictPass` | pairs formed over the whole store, judge requests answered in this run, pairs still pending |
| `documents[].suspect[]` | per claim that gates or warns, its most severe status, such as `evidence:changed`, `judge:pending`, `conflict`, `expired`, `superseded` |

`--explain` adds `detail` to each verdict: `docRegion`, `evidenceRegions[]`, `similarity`, and `changes[]` (`{ path, kind: text | ast | value, detail }`). `hibi schema --name Verdict` prints the schema.

`--doc` and `--since` scope the verdicts. The contradiction pass still runs over the whole store, so a scoped check sees a conflict with a claim outside its scope.

## Output format

Human output on a terminal, JSON when piped. `--format human|compact|json|json-pretty` or `--json` overrides. `--overview` renders a per-document table in human output.
