A claim has a **doc side**, the sentence in its document. `code` and `reference` claims also have **evidence sides**: one or more code spans for `code`, exactly one span in another document for `reference`. `attested` claims have no evidence side. See [Claims](/claims).

Each side is a **selector bundle**: one file plus a list of selectors that point at the same span in different ways.

```json
{ "file": "src/retry.ts", "selectors": [ { "kind": "text-quote", … }, { "kind": "text-position", … } ] }
```

The store holds the selectors, not a copy of the file. At check time hibi re-reads each file from the working tree and locates the span again. `check` never reads git history.

## Selector kinds

| selector | sides | what it stores |
|---|---|---|
| `text-quote` | all | the exact text, plus up to 48 characters of prefix and suffix context |
| `text-position` | all | the character offsets at record time; a locate bias and the `moved` tiebreaker |
| `ast-node` | code spans | the smallest enclosing named tree-sitter node, with a structural hash and a semantic hash; used for reason labels |
| `value` | code spans | the first literal inside the quoted span, so `5` becoming `50` is caught |

Doc sides and `reference` evidence sides store `text-quote` and `text-position` only.

The `value` selector is stored only when a literal lies inside the quoted span. Quote the load-bearing token (`MAX_ATTEMPTS = 5`), not the whole line.

## Tree-sitter

The official tree-sitter grammars for these languages are embedded in the hibi binary; nothing is downloaded. Hibi loads them per language, only for the files being checked:

| language | extensions |
|---|---|
| TypeScript and JavaScript | `.ts`, `.js`, `.mjs`, `.cjs` |
| TSX and JSX | `.tsx`, `.jsx` |
| Python | `.py`, `.pyi` |
| Rust | `.rs` |
| Go | `.go` |
| Java | `.java` |

A code span in any other language gets `text-quote` and `text-position` only, with no warning. `--no-ast` skips tree-sitter entirely: no `ast-node` or `value` selector is recorded, and at check time stored `ast-node` and `value` selectors are not compared.

A code span without structural checks (under `--no-ast`, or in a language with no grammar) falls back to the numeric-token rule that doc spans use: the side is `changed` when the numbers in the located text differ from the numbers in the stored quote. The located text is widened to whole numbers at its edges, so a quote `= 5` that now matches the start of `= 50` reads `= 50` and is caught.

## The resolution cascade

Each side is resolved by an ordered cascade. There is no weighted score.

<Steps>
  <Step title="Locate the quote">
    Find exact occurrences of the stored quote. If there are several, rank them by how well the stored prefix and suffix match. If there is no exact occurrence, run a bitap fuzzy match biased toward the stored position. The match is accepted only when its edit distance to the stored quote is within `min(256, floor(len × 0.4))`, where `len` is the quote length.
  </Step>
  <Step title="Not found: orphaned">
    A missing file, or no match within the budget, is `orphaned`.
  </Step>
  <Step title="Several equally good exact matches: ambiguous">
    When more than one exact occurrence ties on context, the side is `ambiguous`. Quotes shorter than 8 characters are exempt; their candidates are picked by position.
  </Step>
  <Step title="Changed">
    The side is `changed` when any of these holds: normalized text similarity to the stored quote is below 0.9; the semantic AST hash differs; the literal inside the span differs from the stored value; on a span without structural checks (a doc or reference span, or a code span under `--no-ast` or with no grammar), a number in the text changed, reading whole numbers at the span edges.
  </Step>
  <Step title="Unchanged or moved">
    Otherwise the text is the same. If the located start is within 4 characters of the stored position, the side is `unchanged`; further away, it is `moved`.
  </Step>
</Steps>

Position is only a bias during locate and the tiebreaker between `unchanged` and `moved`. It never decides `changed`.

A claim with several evidence sides reports the worst one on the `evidence` axis, in this order from worst: `orphaned`, `ambiguous`, `changed`, `unavailable`, `moved`, `unchanged`.

## Reason labels

Every side's labels appear in the verdict's `reasons[]`, prefixed `doc: ` or `evidence: `. A `changed` side also adds entries to `detail.changes[]` (shown with `--explain`), each `{ path, kind, detail }`. The first change is repeated in the verdict's one-line `changed` field, for example ``src/retry.ts value: value changed (was `5`)``.

| condition | label | `changes[].kind` |
|---|---|---|
| in-span literal differs | ``value changed (was `5`)`` | `value` |
| semantic hash differs, structural hash equal | `identifiers or literals renamed` | `ast` |
| both hashes differ | `restructured` | `ast` |
| a number in a span without structural checks differs | `a number in the sentence changed` | `text` |
| similarity below 0.9 | `text changed (NN% similar)` | `text` |
| quote not located | `quote not found` | `text` |
| file missing | `file not found: <path>` | `text` |
| several equal matches | `quote matched in several places equally well` | none |
| same text at a new offset | `span moved N chars` | none |

## The constants

All resolution constants live in `src/algo/params.ts`. There are no hidden weights.

| constant | value | effect |
|---|---|---|
| fuzzy error budget | `min(256, floor(len × 0.4))` edits | a candidate over it is `orphaned` |
| text-quote context | 48 characters each side | ranks exact occurrences |
| same-text similarity | 0.9 | below it, `changed` |
| move awareness | 4 characters | beyond it, same text is `moved` |
| ambiguity minimum quote length | 8 characters | shorter quotes are never `ambiguous` |

## Sides in another repository

`config.repos` in `.claims/config.json` maps an alias to a directory relative to the repository root:

```json
{ "repos": { "api": "../api" } }
```

An evidence side's file may then be `api:src/limits.ts`. At check time:

| situation | state | reason label |
|---|---|---|
| the directory exists | resolved like any other side | |
| the directory does not exist | `unavailable` | `sibling repo "api" is not checked out at ../api` |
| the alias was removed from config | `unavailable` | `repo alias "api" is not defined in .claims/config.json repos` |
| the path resolves outside the alias directory or the anchor root | `unavailable` | `path escapes its root` |

`unavailable` warns and never gates. Without aliases nothing changes. `hibi reanchor` keeps a side whose sibling repo is not checked out unchanged, with a warning.

## Anchors and the judge

For a `reference` claim, the judge is asked whether the referenced text still supports the sentence only when both sides were located as `unchanged` or `moved`. Otherwise the verdict carries a label such as `judge: not consulted while the doc side is changed` or `judge: not consulted while the evidence side is orphaned`, and the anchor state decides the outcome. Fix the anchor first; the judge runs on the next `check`.

## Record-time checks

`record` and `reanchor` refuse:

- a doc quote shorter than 8 characters;
- a quote or range that does not occur in its file, or covers only whitespace;
- an evidence file that does not exist on disk;
- an evidence file outside its root: the anchor root, or the alias directory for an aliased file (`path escapes its root`);
- an alias that `config.repos` does not define.

Paths are normalized to POSIX paths relative to the anchor root before they are stored, so `./src/retry.ts` and `src/retry.ts` are the same file.

A doc quote that occurs more than once is refused when the stored context cannot single out one occurrence, and recorded with a warning when it can. Widen the span with `--doc-range` to avoid both.
