---
title: "What stales a claim"
description: "Fingerprints: which edits change them and which do not."
---

A mark holds one fingerprint per side. A claim is fresh only while the current
fingerprint of every side is byte for byte equal to the one in some mark.
Whether an edit stales a claim is therefore a question of whether it changes a
fingerprint.

A fingerprint looks like `b3:ast-v1:fb3a4a42c90a9093fe98969b8a0018c0`: the
hash function (BLAKE3), the profile that normalized the text, and the first 16
bytes of the digest in hex.

## Prose and plain text: `prose-v1`

Used for prose units (sentences, headings, list items, table rows, fenced
blocks), for blocks of plain text, and for the whole-file unit of a file that
has no syntax tree.

The text is normalized to Unicode NFC, every run of whitespace becomes one
space, and the result is trimmed. So re-wrapping a paragraph or changing
indentation does not stale a claim. Changing any word, number or punctuation
mark does.

## Code: `ast-v1`

Used for declarations and top-level statements of TypeScript, TSX (and
JavaScript), Python, Rust, Go and Java, and for the whole-file unit of a code
file that parsed without error. The fingerprint is a hash of the unit's syntax
tree, not of its text.

| Edit | Stales the claim |
|---|---|
| Whitespace, indentation, line breaks | No |
| A Python backslash line continuation, as in `TOTAL = 1 + \` followed by `2` on the next line, added or removed | Yes |
| Adding, removing or changing a comment, including doc comments, anywhere | No |
| A trailing comma before `)`, `]`, `}` or `>` | No |
| The comma that makes a one-element tuple, as in Python `X = (1,)` | Yes |
| The shared part of a declaration with several names, such as the type in Java `int width, height;` or `const` versus `let` in TypeScript `const LIMIT = 64, MAX = 128;` | Yes, for each name |
| The ABI string of a Rust `extern "C" { ... }` block, or its attributes | Yes, for each item in it |
| In Go, the expression of an earlier constant that a later constant without its own expression repeats (`iota`) | Yes, for the later constant too |
| A changed literal (number, string, character) | Yes |
| A changed identifier, operator or keyword | Yes |
| Adding or removing a node | Yes |
| Adding or removing parentheses | Yes |
| Adding or removing semicolons | Yes |
| Changing quote style, such as `"` to `'` | Yes |
| A change to a Python docstring | Yes, a docstring is a string |

In short: reformatting that changes only whitespace, line breaks, comments or
a trailing comma keeps claims fresh. The one line break that counts is a
Python backslash continuation. A formatter that changes semicolons, quote
style or parentheses stales claims, and each stale claim needs a re-check and
a `mark`.

### Examples

This Rust file was reformatted: the constant split over two lines, a comment
added after it, and the function signature spread over three lines with a
comment in its body:

```rust
/// How often a download is tried before the client gives up.
pub const MAX_ATTEMPTS: u32 =
    3; // keep in sync with the docs

/// The delay before attempt `n`, in milliseconds.
pub fn delay_ms(n: u32)
    -> u64
{
    // doubles each time
    200 * 2u64.pow(n)
}
```

The claim on it stayed fresh:

```text output
$ hibi status
2 claims: 1 fresh, 0 stale, 0 expired, 1 retired
nothing stale
```

In TypeScript, splitting `sum(a: number, b: number)` and `return [a, b];` over
several lines with trailing commas left its claim fresh. Wrapping the returned
array in parentheses, `return ([a, b]);`, made it stale:

```text output
$ hibi status --loc "file:src/sum.ts"
4 claims: 3 fresh, 1 stale, 0 expired, 0 retired

c1-zsb4rm615vww8aphg2m0  stale  sum returns both numbers.
  marked 2026-11-21T06:36:10Z (m1-yg550z3geyd24p5a2fmd)
  evidence 1  file:src/sum.ts  changed (fingerprint_differs)  function "sum", lines 1-3
  next: hibi mark c1-zsb4rm615vww8aphg2m0

Re-check each statement before running its next command. If it no longer holds, fix the text or the code, or retire the claim with hibi retire.
```

## A file that does not parse

A code file whose syntax tree has an error has no declarations for that run.
A side whose stored anchor has a symbol is then `unavailable` with reason
`resource_unavailable`. An anchor into a declaration stores its symbol also
when you gave only a quote. The message names the first error line, the
side's `remediation` repeats it, and `next` is `null`, because no hibi
command fixes a syntax error:

```text output
c1-zsb4rm615vww8aphg2m0  stale  sum returns both numbers.
  marked 2026-11-21T06:36:10Z (m1-yg550z3geyd24p5a2fmd)
  evidence 1  file:src/sum.ts  unavailable (resource_unavailable)
    file:src/sum.ts does not parse as typescript (the first error is on line 2), so its declarations cannot be found; fix the syntax error. Run the command again once that is fixed.
```

Fix the syntax error and the side is resolved again.

For that run the file is read as plain text, in blocks with `prose-v1`
fingerprints, so an anchor without a symbol, such as the whole file, still
resolves. Its fingerprint then has another profile than the marked one, and
the side is `unavailable` with reason `profile_mismatch`:

```text output
c1-qg42h10vrpejrffzc9gc  stale  size.ts sets the size.
  marked 2026-11-21T06:36:14Z (m1-ah3tj26be9tyqkbkr72t)
  evidence 1  file:src/size.ts  unavailable (profile_mismatch)  file "export const SIZE = 8; export const = ;", lines 1-2
  next: hibi mark c1-qg42h10vrpejrffzc9gc
```

Two fingerprints of different profiles are never compared.
`profile_mismatch` therefore occurs when a code file that parsed at the mark
no longer parses, or the reverse, for an anchor without a symbol; when a
later hibi ships a new profile version; and when an external provider changes
the profile name it puts in its fingerprints.

Renaming a file, also to another extension, is not a profile mismatch: the
locator names the old path, so the side is missing and `next` asks for a new
anchor. Renaming `src/lim.rs` to `src/lim.py` gives:

```text output
c1-4tsrbh9asdmr6jh963hs  stale  The cache holds 64 entries.
  marked 2026-11-21T06:36:16Z (m1-pfbs3xqw5nk2bj6n5sng)
  evidence 1  file:src/lim.rs  missing (resource_not_found)
    stored: symbol LIMIT, quote "pub const LIMIT: u32 = 64;"
  next: hibi reanchor c1-4tsrbh9asdmr6jh963hs --evidence 1=<anchor>
```

## Versioning

The grammar versions are part of `ast-v1`. A hibi release that changes a
grammar or a rule of the tree hash must use a new profile name, so the change
shows as `profile_mismatch` instead of silently staling or freshening claims.
`hibi version` lists the profiles and grammar versions of the build:

```bash
hibi --format json version
```

```json output
{"ok":true,"command":"version","version":"5.0.0","protocol":[1],"storeVersion":1,"profiles":["prose-v1","ast-v1"],"grammars":{"go":"0.25.0","java":"0.23.5","python":"0.25.0","rust":"0.24.2","tsx":"0.23.2","typescript":"0.23.2"},"judgeModel":"jev-1.14.0","warnings":[]}
```
