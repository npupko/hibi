---
title: "Anchors and selectors"
description: "How a claim points at a sentence, a function or a field, and finds it again after edits."
---

An anchor is a locator plus a selector. The locator names a resource; the
selector picks one unit inside it and lets hibi find that unit again after
the file is edited.

## Locators

| Form | Names |
|---|---|
| `file:<path>` | A file relative to the root (the directory that contains `.hibi/`). Paths use `/`. When git can be used, the path must be one git lists there, with the same letter case; see [the file provider](/providers/file#resource-classes). |
| `repo:<alias>//<path>` | A file in a sibling repository. The alias is declared in `.hibi/hibi.toml` and its directory is allowed in your user config. See [configuration](/configuration#sibling-repositories). |
| `<scheme>:<anything>` | A resource of an [external provider](/providers/external). hibi passes the part after the colon through unchanged. |

## Selectors

| Key | Meaning |
|---|---|
| `quote` | Text that occurs in the unit. Matched as given, untrimmed. |
| `prefix`, `suffix` | Up to 48 characters before and after the quote. Allowed only with `quote`. |
| `pos` | The byte offset of the quote when it was recorded. A hint only. Allowed only with `quote`. |
| `symbol` | The declaration path of a code unit, such as `MAX_ATTEMPTS`, `Config.timeout_secs` or `Store.get`. |
| `key` | A unit key, for external providers that address units by key. The file provider does not accept it. |

The empty selector `{}` selects the whole resource (its `file` unit).

## Compact anchors on the command line

`--subject`, `--evidence` and the other anchor options take a compact string:

| Compact anchor | Selects |
|---|---|
| `file:docs/retry.md` | The whole file |
| `file:src/retry.rs#delay_ms` | The declaration with this symbol |
| `file:docs/retry.md::gives up after 5 attempts` | The unit that contains this quote |
| `file:src/retry.rs#delay_ms::200` | A quote inside a symbol |

The part after the first `::` is the quote, taken verbatim. The part between
`#` and `::` is the symbol. For an external scheme, a compact anchor is the
locator alone, with the empty selector.

Some anchors cannot be written in compact form: a path that contains `#` or
`::`, and any selector other than the empty one for an external scheme (such
as a `key`). Give those as an object `{"loc": ..., "sel": {...}}`. An anchor
option whose value starts with `{` is read as such an object, also after the
`n=` of `reanchor --evidence`, and in a
`hibi claim --stdin` document an anchor is either a compact string or an
object. This example assumes the scheme `ref` is declared in `.hibi/hibi.toml`
and its provider is registered in your user config (see
[external providers](/providers/external)):

```bash
echo '[{"statement": "Downloads are retried at most 3 times.", "subject": {"loc": "ref:notes", "sel": {"key": "n1"}}, "evidence": ["file:src/retry.rs#MAX_ATTEMPTS"]}]' | hibi claim --stdin
```

## Stored anchors are completed

hibi never stores a selector as you typed it. It resolves the anchor and
stores the selector the provider returns for the unit it found. For the file
provider that is the quote, up to 48 characters before and after it, its
byte position, and the symbol when the unit is a declaration. For a
declaration whose symbol is unique in the file, the characters before and
after are taken only from the declaration's own scope, so they are short.
This is what `reanchor` printed for the walkthrough's claim:

```text output
  subject file:docs/retry.md (sentence "It gives up after 3 attempts.", line 4)
    {"loc":"file:docs/retry.md","sel":{"quote":"gives up after 3 attempts","prefix":"tries\n\nThe client retries a failed download.\nIt ","suffix":".\nThe delay between attempts doubles each time, ","pos":52}}
  evidence 1 file:src/retry.rs (variable "MAX_ATTEMPTS", line 2)
    {"loc":"file:src/retry.rs","sel":{"quote":"pub const MAX_ATTEMPTS: u32 = 3;","prefix":"\n","suffix":"\n\n","pos":62,"symbol":"MAX_ATTEMPTS"}}
```

The evidence was given as `#MAX_ATTEMPTS` only; hibi added the first line of
the declaration as its quote.

## Finding the unit

A quote that differs from the text only in whitespace, for example after a
paragraph was re-wrapped, counts as an exact occurrence.

**A new anchor**, as you type it, has a quote but no stored context. Every
exact occurrence of the quote is a candidate and nothing chooses between
them. Occurrences inside one unit resolve to that unit. Occurrences in more
than one unit are `side_ambiguous`, whatever the length of the quote. The
error lists every candidate with an anchor that selects it, so you can pass
one of those, make the quote longer, or add a symbol:

```text output
$ hibi claim "x" --subject "file:docs/cache.md::The cache"
error: side_ambiguous: the subject (file:docs/cache.md): the anchor matches 2 units; use one of these anchors: sentence "The cache holds 64 entries.", line 3: {"loc":"file:docs/cache.md","sel":{"quote":"The cache holds 64 entries.","prefix":"# Cache\n\n","suffix":"\nOld entries are evicted first.\nThe cache is cle","pos":9}}; sentence "The cache is cleared on restart.", line 5: {"loc":"file:docs/cache.md","sel":{"quote":"The cache is cleared on restart.","prefix":"olds 64 entries.\nOld entries are evicted first.\n","suffix":"\n","pos":68}}
  fix: Give a symbol, or a longer quote, so that the anchor matches one unit.
```

**A stored anchor** is resolved on every later run:

1. A `symbol` that names exactly one declaration selects it. The quote then
   only decides which text the stored selector keeps.
2. A `symbol` that names several declarations, such as Python `@overload`
   stubs or a function defined twice, is compared with each of them. The
   quote and the context stored around it are looked for in each
   declaration. The one declaration that reproduces them exactly is
   selected, so an anchor stored while the symbol was unique keeps
   following that declaration after copies appear. When none reproduces
   them and one is closer than the others, that one is a candidate, for
   example a stub whose signature changed. Otherwise the side is
   `ambiguous`. The position in the file never chooses.
3. Without a symbol, the quote is searched. One exact occurrence selects the
   unit that contains it. Several exact occurrences are told apart by the
   similarity of the 48 characters before and after them. A tie goes to the
   occurrence nearest `pos` when the quote is under 8 characters, and is
   `ambiguous` otherwise.
4. Anything else resolves to no unit. When a symbol names no declaration, or
   the quote has no exact occurrence, the side is `missing` with reason
   `not_exact`. The units that the quote still finds, exactly or by a fuzzy
   search near `pos` with up to 40% of its characters changed (at most 256),
   are listed as **candidates**.

A claim on `def limit()` in `src/queue.py` stays fresh after a second
`def limit()` with another body is added above it, and follows the original,
now on lines 4-5:

```text output
$ hibi status --detail c1-5eaf
4 claims: 3 fresh, 1 stale, 0 expired, 0 retired

c1-5eaf6x2yrjb6xrkx2yqe  fresh  The queue holds 100 jobs.
  marked 2026-11-21T04:20:23Z (m1-bbktvyzqnjrvgpmewc1j)
  subject  file:README.md  same  sentence "The limit is applied per worker.", line 5
    | The limit is applied per worker.
  evidence 1  file:src/queue.py  same  function "limit", lines 4-5
    | def limit():
    |     return 100
```

Two declarations of one symbol that are identical, byte for byte, and have
identical text around them cannot be told apart. A side anchored to either
is `ambiguous`. Make them differ, or anchor the code that contains them.

Similarity proposes and never resolves. A candidate is never used as the
side's unit: the claim is stale, `mark` refuses it, and `next` asks you for
an anchor. Each candidate carries an anchor that selects it alone, so after
you have read it you can pass that anchor to `reanchor`. Freshness is always
exact [fingerprint](/concepts/fingerprints) equality.

The anchor of a candidate, and of each unit an ambiguity error lists, is
`<loc>#<symbol>` when that symbol occurs once in the whole file, and the
unit's full anchor as JSON otherwise. At most 20 are listed, with the count
of all of them. A new anchor whose symbol names several declarations is
`ambiguous` and lists every one; each listed anchor carries context cut from
that declaration's own surroundings. Two Python functions with the same name
give JSON anchors:

```text output
$ hibi claim "x" --subject "file:README.md::A job runs" --evidence "file:src/jobs.py#run"
error: side_ambiguous: evidence 1 (file:src/jobs.py): the anchor matches 2 units; use one of these anchors: function "run", line 1: {"loc":"file:src/jobs.py","sel":{"quote":"def run(job):","prefix":"","suffix":"\n    return job\n\n","pos":0,"symbol":"run"}}; function "run", line 4: {"loc":"file:src/jobs.py","sel":{"quote":"def run(job, retries):","prefix":"\n\n","suffix":"\n    return job\n\n","pos":30,"symbol":"run"}}
  fix: Give a symbol, or a longer quote, so that the anchor matches one unit.
```

## Write checks: every side resolves exactly

When an anchor is new (in `claim`, or a replaced or added side in
`reanchor`), it must resolve to exactly one unit, exactly:

```text output
$ hibi claim "Attempts are tried" --subject "file:docs/retry.md::retries a faild download"
error: selector_not_exact: the subject (file:docs/retry.md): the anchor matches no unit exactly; 1 unit was found by similarity, each a guess to check before use: sentence "The client retries a failed download.", line 3: {"loc":"file:docs/retry.md","sel":{"quote":"The client retries a failed download.","prefix":"# Retries\n\n","suffix":"\nIt gives up after 3 attempts.\nThe delay between","pos":11}}
  fix: Give a quote that occurs exactly in the unit you mean.
```

```text output
$ hibi claim "Attempts are tried" --subject "file:docs/retry.md::nothing like this"
error: side_missing: the subject (file:docs/retry.md) resolves to no unit (selector_not_found): the selector matches no unit
  fix: Point the anchor at text that exists in the resource.
```

With `#symbol::quote`, the quote must occur inside that declaration. A quote
that is not found there, such as text from a doc comment written above the
declaration, makes the anchor `selector_not_exact` (or `quote_in_comment` when
the quote lies in a comment inside it):

```text output
$ hibi claim "x" --subject "file:docs/cache.md::holds 64 entries" --evidence "file:src/cache.rs#Cache::Settings read at start-up"
error: selector_not_exact: evidence 1 (file:src/cache.rs): the quote "Settings read at start-up" does not occur in the unit the anchor resolves to; found struct:Cache (struct) at line 2: Cache, text "pub struct Cache {\n    pub limit: u32,\n}"
  fix: Quote text that occurs in that unit, or leave the quote out to anchor the whole unit.
```

A quote copied from a member line keeps its leading indentation and a
trailing `,` or `;` and still resolves to that member: `file:src/pair.rs::    pub left: u32,`
selects the field `Pair.left`.

A quote must lie inside one unit, also when a symbol names several
declarations:

```text output
$ echo '[{"statement":"x","subject":"file:docs/retry.md::download.\nIt gives"}]' | hibi claim --stdin
error: element 0: quote_spans_units: the subject (file:docs/retry.md): the quote reaches outside one unit
  fix: Quote text from one unit only.
```

A `#symbol` needs a file with declarations. On a markdown, prose or plain
text file it is refused:

```text output
$ hibi claim "x" --subject "file:README.md#Jobs"
error: invalid_anchor: the subject (file:README.md): file:README.md is a markdown file, and this kind of file has no symbols; anchor it with a quote instead
  fix: Change the anchor as the message says. hibi claim --help describes the anchor forms.
```

`mark` and a `reanchor` that keeps a side make the same check on the stored
anchor: every side must resolve to exactly one unit. A side that is missing
or ambiguous makes them fail with `side_missing` or `side_ambiguous`, and the
error lists the candidates.

## Quotes inside code comments cannot be anchored

The code fingerprint ignores comments, so a claim anchored to a comment could
never go stale. A quote that lies wholly or partly inside a comment is
refused, and that includes documentation comments: JSDoc, rustdoc and
Javadoc.

```text output
$ hibi claim "The request timeout is stored in whole seconds." --subject "file:README.md::stored in whole seconds" --evidence "file:src/config.rs#Config::Seconds before a request"
error: quote_in_comment: evidence 1 (file:src/config.rs): the quote lies wholly or partly inside a code comment
  fix: Anchor the code the comment describes.
```

A Python docstring is a string, not a comment. It is part of the fingerprint
and can be anchored:

```text output
$ hibi claim "Jobs run at most 3 times." --subject "file:src/jobs.py#Job::Jobs run at most 3 times" --evidence "file:src/jobs.py#Job.retries"
c1-qvbjt2ph1pgeyxqzpj2w  created  m1-s74e3b2z2w577d5jt1by  subject file:src/jobs.py (class "Job", lines 1-8); evidence 1 file:src/jobs.py (field "Job.retries", line 4)
```

## Renames

hibi keeps no alias for a renamed or moved unit. When a stored symbol names
no declaration, the side is `missing`, and the claim is stale until someone
re-anchors it. The units the stored quote still finds are candidates. Renaming
the Python function `limit` to `queue_limit` gives:

```text output
$ hibi status
3 claims: 1 fresh, 2 stale, 0 expired, 0 retired

c1-3mz8p0vyhcqppgjbvtyh  stale  limit returns 100.
  marked 2026-11-21T04:17:17Z (m1-da0wgcz2hb5pj1ha4yzd)
  evidence 1  file:src/jobs.py  missing (not_exact)
    stored: symbol limit, quote "def limit():"
    1 candidate, found by similarity; each is a guess, read it before you anchor to it:
    - function "queue_limit", line 7
      | def queue_limit(): return 100
      anchor: file:src/jobs.py#queue_limit
  next: hibi reanchor c1-3mz8p0vyhcqppgjbvtyh --evidence 1=<anchor>

c1-wza47tv2t7g9czrk16x4  stale  The queue holds 100 jobs.
  marked 2026-11-21T04:17:17Z (m1-mw6py7trnfqqht89y2qz)
  evidence 1  file:src/jobs.py  missing (not_exact)
    stored: symbol limit, quote "def limit():"
    1 candidate, found by similarity; each is a guess, read it before you anchor to it:
    - function "queue_limit", line 7
      | def queue_limit(): return 100
      anchor: file:src/jobs.py#queue_limit
  next: hibi reanchor c1-wza47tv2t7g9czrk16x4 --evidence 1=<anchor>

Re-check each statement before running its next command. If it no longer holds, fix the text or the code, or retire the claim with hibi retire.
```

Read the candidate. If it is the same function and the statement still
holds, anchor to it:

```text output
$ hibi reanchor c1-3mz8 --statement 'queue_limit returns 100.' --evidence 1=file:src/jobs.py#queue_limit
c1-3mz8p0vyhcqppgjbvtyh is retired and replaced by the new claim c1-gnn5034a914fjregkzbx
  mark m1-sp8ffyqgs7t0pn1m1xhw, retirement r1-ed5hq4avvf4d7ng9st4k
  was stale: evidence 1 file:src/jobs.py missing (not_exact); now marked
  subject file:README.md (sentence "The limit is applied per worker.", line 5)
    {"loc":"file:README.md","sel":{"quote":"The limit is applied per worker.","prefix":"runs at most 3 times.\nThe queue holds 100 jobs.\n","suffix":"\n","pos":62}}
  evidence 1 file:src/jobs.py (function "queue_limit", lines 7-8)
    {"loc":"file:src/jobs.py","sel":{"quote":"def queue_limit():","prefix":"\n\n","suffix":"\n    return 100\n","pos":69,"symbol":"queue_limit"}}
```

Here the statement named the function, so it changed too. A rename that
changed most of a short first line can leave no candidate. Renaming
`JOB_LIMIT = 100` to `MAX_JOBS = 100` gives:

```text output
$ hibi status
4 claims: 3 fresh, 1 stale, 0 expired, 0 retired

c1-5hktdkt5a4dmvmc90eec  stale  At most 100 jobs are queued.
  marked 2026-11-21T04:25:05Z (m1-wbqvcdbbgztd9rp2v87m)
  evidence 1  file:src/jobs.py  missing (selector_not_found)
    stored: symbol JOB_LIMIT, quote "JOB_LIMIT = 100"
  next: hibi reanchor c1-5hktdkt5a4dmvmc90eec --evidence 1=<anchor>

Re-check each statement before running its next command. If it no longer holds, fix the text or the code, or retire the claim with hibi retire.
```

A rename of an enclosing container (a struct, class or module) changes a
member's path but not the member's content. The member is a candidate with
"same content as at the last mark" (`sameFingerprint: true` in JSON).
Renaming the struct `Config` to `Settings` gives, for a claim on its field
`Config.timeout_secs`:

```text output
$ hibi status
4 claims: 3 fresh, 1 stale, 0 expired, 0 retired

c1-d0a4yrq9pmv59dc0ggqa  stale  The request timeout is stored in whole seconds.
  marked 2026-11-21T04:25:05Z (m1-q7msyvy1q1gv2zer63c3)
  evidence 1  file:src/config.rs  missing (not_exact)
    stored: symbol Config.timeout_secs, quote "pub timeout_secs: u32"
    1 candidate, found by similarity; each is a guess, read it before you anchor to it:
    - field "Settings.timeout_secs", line 5; same content as at the last mark
      | pub timeout_secs: u32
      anchor: file:src/config.rs#Settings.timeout_secs
  next: hibi reanchor c1-d0a4yrq9pmv59dc0ggqa --evidence 1=<anchor>

Re-check each statement before running its next command. If it no longer holds, fix the text or the code, or retire the claim with hibi retire.
```

The field has the content that was checked, so after reading it,
`hibi reanchor c1-d0a4 --evidence 1=file:src/config.rs#Settings.timeout_secs`
stores the new symbol.
