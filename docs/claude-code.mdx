Hibi ships a [Claude Code](https://claude.com/claude-code) skill: instructions the agent loads when it works with hibi. The primary user of hibi is a coding agent, and the skill teaches it the commands, the JSON shapes, and the rules for clearing a flag.

## Install

The repository is also a plugin marketplace.

```
/plugin marketplace add npupko/hibi
/plugin install hibi-cli@hibi
```

Claude loads the skill when you ask it to work with hibi. You can also invoke it as `/hibi-cli:hibi`. Run `/plugin marketplace update` to get a newer version.

The skill does not include the `hibi` binary. Install hibi with the prebuilt binary or `bun add @npupko/hibi` (see [Quickstart](/quickstart)).

## The instruction line

An agent that never loads the skill still needs to know when to ask hibi. `init --instructions` appends one line to an agent instruction file, and creates the file if it is missing:

```sh
hibi init --instructions CLAUDE.md   # or AGENTS.md
```

The line it appends:

```text
Before relying on a document, run `hibi check --doc <file>`; exit 2 means a sentence in it is stale.
```

If the line is already in the file, `init` does not add it again. The JSON result reports `instructions: { file, appended }`.

## What the skill teaches

The skill covers the agent loop described in [Workflows](/workflows):

- **Before trusting a document**, run `hibi check --doc <file>` and do not act on a sentence whose verdict gates.
- **For a new document**, run `hibi audit --doc <file>`, then record the claims it finds with `hibi record --from-file - --by agent:<name>`. The agent chooses the kind, the anchors, the sources, and the procedure. Hibi never records on its own.
- **After a change**, run `hibi check --since <ref>` and follow each verdict's `remediation`.
- **Before trusting a document with no claims**, expect `hibi check --doc <file>` to exit 1 with `no claims are registered for <file>`, and run `hibi audit --doc <file>` instead.
- **For the worklist**, follow each `attested` item's `procedure` and `sources`, collect the evidence, and submit it with `hibi evidence --from-file - --by agent:<name>`. Evidence applies to `attested` claims only.
- **For findings**, reconcile a contradiction by fixing the wrong sentence, or acknowledge a finding with `hibi attest <id> --by agent:<name> --ack review --note "<why>"` or `hibi attest <id> --by agent:<name> --ack conflict:<other-id> --note "<why>"`. Each `remediation` action's `command` runs as printed once its placeholders are filled in.

The skill also states what an agent must not do:

- vouch as a human. An agent attests as `agent:<name>`. Its vouch is recorded and does not reset a ttl. Only judged evidence or a `human:` vouch does (see [Attestations](/attestations)).
- reanchor a claim without re-reading the sentence against its evidence.
- delete a file under `.claims/` instead of running `hibi retire <id>`.

## Session hooks

You can run the two read-only checks from Claude Code hooks in your own settings:

| hook | command |
|---|---|
| `SessionStart` | `hibi check --doc CLAUDE.md` |
| `Stop` | `hibi check --since origin/main` |

Hibi ships no hook configuration. Both commands write nothing except judge cache entries.
