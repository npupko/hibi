## The problem

Repositories hold more than code. They hold instruction files (`CLAUDE.md`, `AGENTS.md`), READMEs, decision records, process pages, and whole knowledge repositories of policies, prices, and facts about the outside world. Coding agents load these files and act on every line. The sentences in them go stale in three ways:

| what changed | example |
|---|---|
| the code | a page says "retries 5 times" after the constant became `50` |
| another document | a page says "refunds within two weeks" after the billing guide changed to 14 days |
| the world | a page says "Pro costs $29" after the price changed in the billing dashboard |

Only the first can be detected by reading the repository's code. Hibi covers all three, with one claim kind each: `code`, `reference`, and `attested` (see [Claims](/claims)). It also finds sentences that contradict each other and sentences nothing could ever verify.

## The threat model

**A reader asks hibi before trusting a file.** The reader is usually an agent that runs `hibi check --doc <file>` and reads the exit code and JSON. Hibi does not try to reach readers that do not ask. `init --instructions` adds one line to an agent instruction file so the agent knows to ask.

## Principles

<AccordionGroup>
  <Accordion title="1. Hibi runs nothing and fetches nothing" icon="hand">
    No command execution, no URL fetching, no network except the judge API. A claim can carry a procedure and sources, but an agent or an outer runner carries them out and submits the evidence with `hibi evidence`.
  </Accordion>

  <Accordion title="2. Same tree, same verdicts" icon="equals">
    Anchor resolution is deterministic. Judge verdicts are cached by model and exact request, and never asked again for the same input, so a second run cannot change them.
  </Accordion>

  <Accordion title="3. A flag means re-verify" icon="flag">
    Hibi reports that evidence moved, expired, was refuted, or conflicts. It never rewrites prose and never declares a sentence false on its own authority.
  </Accordion>

  <Accordion title="4. Nothing clears without evidence or a human" icon="user-check">
    An agent cannot vouch a claim fresh. Evidence the judge found to support the sentence, or a `human:` attestation, can. See [Attestations](/attestations).
  </Accordion>

  <Accordion title="5. One knob per concept, no hidden rules" icon="sliders">
    One judge threshold for every judgment. Every automatic rule that fires appears as a reason label in the report.
  </Accordion>

  <Accordion title="6. Contracts are data" icon="file-code">
    The store schema, the judge request and response shapes, and the judge questions are JSON. Tests use JSON fixtures. The implementation language can be replaced.
  </Accordion>
</AccordionGroup>

## Why a model sits on the verdict path

Text anchoring can tell that a referenced span changed. It cannot tell whether "Refunds are issued within two weeks of a request" is still supported by "Refunds are issued within 14 days", or whether evidence an agent pasted from a dashboard supports a price. Those questions need a reader. Hibi asks one, with limits:

- **One small interface.** Three judgments: `triage` (what kind of region is this), `supports` (does this evidence support this sentence), and `conflict` (do these two sentences contradict). Jev, from TypeSafe, is the only shipped implementation. See [Judge](/judge).
- **One threshold, three outcomes.** A judgment gates, goes to `review` (a warning), or is clean. `judge.threshold` in `.claims/config.json` sets the line for all of them.
- **Numbers stay in code.** Numbers, money, versions, and dates are extracted and compared by code, not by the model.
- **Cached verdicts.** Each answer is stored in `.claims/judge/` under the hash of the pinned model id and the canonical request. The same tree gives the same verdicts on every run and on every machine that has the committed cache.
- **No key means pending.** Without `TYPESAFE_API_KEY`, or with the network down, an unanswered judgment is `pending`, which warns. It is never reported as a pass.

## Why there are no banners

Earlier versions wrote a status comment into each stale document. That was removed:

- An HTML comment is invisible in rendered documentation; only readers of the raw file saw it.
- It needed a write path into every document, a comment syntax per format, and it produced diff churn on every status change.
- The trust call is `hibi check --doc <file>`, which gives the reader the current state instead of the state at the last write.

## What was removed, and why

| removed | reason |
|---|---|
| status comments written into documents | the trust call is `check --doc`; see above |
| commands run by `check` | hibi executes nothing; agent-run procedures and `hibi evidence` replace them |
| the external extension protocol | the judge interface is the one extension point |
| a separate layer of normalized statements | duplicates come from sentence text and the contradiction pass; `supersede` matches sentences verbatim |
| topics | pairing for the contradiction pass is done in code and needs none |
| a `verified` boolean | replaced by attestations with actors and bases |
| store upgrade code | v3 stores are not upgraded |

## Prior art

| prior work | what hibi takes from it |
|---|---|
| Hypothesis fuzzy anchoring | the ordered cascade: exact match with context, then a fuzzy match within an error budget, position as a weak bias |
| W3C Web Annotation Data Model | the `text-quote` and `text-position` selectors; several equal matches is `ambiguous`, not a guess |
| Fiberplane Drift | tree-sitter node fingerprints for code spans |
| Doorstop | a link marked suspect that needs an explicit re-baseline (`reanchor`) |
| RFC Obsoletes, ADR supersession | a superseded document that records its successor (`supersededBy`) |
| FEVER | the `supported` / `refuted` vocabulary, plus "not enough info" as `does_not_address` |
| OKF (Open Knowledge Format) | actor ids (`human:`, `agent:`, `process:`) and the `sources[]` shape |
| Lobster | the step shape of a procedure (`id`, `command`, `stdin`) |
| TypeSafe citation-check cookbook | the three-way `supports` question and the `addresses` check that forces `does_not_address` |
